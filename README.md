# Elysium

一个本地优先的桌面音乐播放客户端（Windows）。前端是本地网页 UI，后端是本地 Python 服务，
窗口用 WebView2 承载——这样既绕开了浏览器跨域限制，也能把界面做得顺手。

> **使用前请先看「声明与边界」**。本项目是个人学习与技术研究的作品，不是商业产品，
> 不提供、不托管、不分发任何音乐内容。请仅在法律与相关条款允许的范围内使用。

界面取向是**发烧友 / 数码音频科技风**，不做单一固定风格，而是给两套底色：

| 主题 | 特征 |
| --- | --- |
| 深色 | 近黑底、卡片化、圆角行 hover、毛玻璃播放条 |
| 浅色 | 白底、发丝分隔线、大字号标题、红色主色 |

两套主题共用同一套骨架（左侧导航轨 + 底栏播放条），差异只在色板、字阶与阴影。
规格列一律用等宽字体 + tabular-nums 对齐，音质用 chip 标注，格式 / 体积 / 时长摊成独立列。

## 功能

**信息架构（歌手 / 专辑 / 收藏）**
- 搜索页分三栏：**歌曲 / 歌手 / 专辑**，后两栏由结果自动归类，点进去就是该歌手或该专辑的完整页面
- **歌手页**：头像、作品统计（首数 / 专辑数 / 无损曲目数）、**歌曲 / 专辑** 两个 tab 平铺，
  曲目一次抓全、按滚动分批渲染
- **专辑页**：封面、简介、曲序表、无损统计，可整张播放 / 整张下载
- **收藏库**：歌曲 / 歌手 / 专辑三类分开归档，左侧轨常驻「我的歌手」「我的专辑」快捷入口
- 收藏是**三态**的（`kind: song | album | artist`），点两次即取消，旧数据自动按 song 兼容

**搜索**
- 单一结果列表：多个音源在后台合并**去重**，同一首只占一行，
  来源只在行内用小徽章标注；另一源也有时徽章变 `⇄`，点一下就地换源（不会多出一行）
- 不重复的曲目直接互补，排序按各源名次交错，不会前半屏全是同一个源
- 同名专辑按「专辑名 + 主艺人」合成一张卡，主来源打不开时自动换备选源
- 支持粘贴专辑、歌单、单曲链接直接解析
- 搜索历史、点歌手名再进歌手页、点专辑名进专辑页
- 搜索结果分页「加载更多」，专辑/歌单可一键全部下载
- 某个源对这个词一条都不给时会**明说**，不会让人误以为没搜到
- 歌手页曲目量与专辑量由**多源深翻页**决定，不再只取前几页那几十首

**发现与统计**
- **为你推荐**：口味画像 + 相似推荐 + 全风格卡片歌单，数据全部本地、零账号；
  候选按「熟悉歌手 + 探索歌手」双池交错生成——探索配额（约 30%）保证每天
  都有一批没听过、但风格顺路的歌掺进来，不会越推越窄；行内 👍/👎 即时影响
  下一轮排序，口味画像页可一键关闭整个推荐
- **我的统计**：首页统计卡——近 7 天收听、累计时长与天数、近 30 天趋势、
  24 小时时段分布、最常听歌手；听完才计，数据只在本地

**播放**
- 在线试听，自动挑可用音质（优先 mp3 320，省流量）
- **无缝播放**：专辑顺序播放时曲末直接接上下一首，不留空档（实测静音 0ms）；
  可选 0.5~2 秒交叉淡入淡出
- **10 段均衡器**：31Hz~16kHz，6 套预设 + 手动微调，即时生效、切预设不爆音
- 播放队列侧栏，点哪首放哪首；队列内拖拽重排，正在播的那首不受影响
- 三种播放模式：顺序 / 单曲循环 / 随机
- 进度拖动、音量、上一首 / 下一首
- 快捷键：空格播放暂停、←/→ 快退快进 5s、↑/↓ 音量、Ctrl+F 聚焦搜索、L 开歌词
- **歌词双语与校准**：上游带翻译时主行下方副行对照（wyy 源多数带，取不到就单语，
  不承诺）；歌词面板与桌面小窗各有一组 ±0.5s 校准按钮——全局持久化
  （正=歌词延后、负=提前，±10s 封顶），改完立即重算当前行
- **系统媒体集成**：桌面端经 `navigator.mediaSession` 直通 Windows SMTC ——
  任务栏媒体浮层、锁屏、键盘媒体键、蓝牙耳机控制全可用；
  Android 端由原生前台服务（通知栏 MediaStyle + 线控 + 音频焦点 + 拔耳机暂停）承接，
  页面里的 `<audio>` 始终是播放的唯一真相源，原生侧只做中转
- **睡眠定时**：15~90 分钟到点暂停，或「播完当前这首就停」（计完收听停在曲末）；会话级，不落盘

**下载**
- 并发队列（1~4 个任务并行），实时速度、剩余时间、进度条
- 目标音质缺失时**自动降级**（FLAC → 320 → 128），不中断
- 下载失败可重试，进行中可取消
- 文件命名模板：`{name} {artist} {album} {platform} {format} {bitrate}`
- 同名文件策略：保留两份 / 覆盖 / 跳过
- 自动识别真实封装（元数据标 mp3 的经常其实是 m4a）
- 可选写入歌曲标签：标题 / 歌手 / 专辑 / 封面 / 歌词
- 可选同时保存 `.lrc`

**本地音乐**
- 侧栏「本地音乐」扫下载目录（含子目录），把已下载的歌接回应用内：标签读标题 / 歌手 /
  专辑 / 时长，读不出就整段用文件名，绝不因单个文件失败中断
- 点行直放本地文件（`/api/local/file` 本地盘 Range 流式，不走在线代理、不进缓存），
  规格 chip 直接显示 mutagen 读出的真实格式与码率，内嵌封面惰性提取
- 收听计数照走 `/api/play`（`platform=local` 只计数，不进在线缓存那套），最近播放 / 继续收听通吃
- 范围刻意克制：只扫下载目录这一个地方，不做全盘扫描、不做标签编辑

**多端同步**
- 收藏 / 歌单 / 播放进度同步到你自己的 WebDAV（坚果云 / NAS），零中转、零账号
- 拉取只算差异、逐项勾选才落盘；同名歌单分歧三选一；本地数据只增不删
- 本地曲目与设置类不同步；凭据只存本机、不回传页面、不进脱敏导出

**桌面歌词**
- 设置里开关一个置顶小窗（frameless、整窗可拖动、贴屏幕右下角），显示当前行 + 下一行 + 封面；
  当前行带翻译时优先显示翻译行
- 数据走本地回环中继（`/api/lyric/now`，纯内存），不落盘、不出本机

**其他**
- 首页：继续收听（带上次进度）、最近播放、我的歌手、我的专辑、快捷搜索
- 收藏夹、搜索历史、最近播放、下载记录，全部存本地
- 歌词查看与保存
- 深色 / 浅色 / 跟随系统三档主题，顶栏一键切换
- 设置抽屉：音质、音量、主题、播放引擎（无缝 / 交叉淡入 / 均衡器）、下载目录、并发、命名模板、同名策略、写标签、缓存上限与清理、数据清理
- 桌面端自绘标题栏与窗口材质，能力不足时静默降级为普通界面

> 缓存只做后台自动维护，界面不提供「缓存歌曲列表」——占用与规则放在设置里看一眼即可。

**更新追踪**
- 双源检查：仓库内 `update.json` 走 jsDelivr 分发（国内可达性远好于 GitHub，且唯一携带直链 / 镜像 / SHA-256），GitHub Releases API 作兜底；谁先通用谁。低频轮询、结果缓存，不打爆 API
- 手动「检查更新」反向优先 GitHub API（最权威、无 CDN 缓存延迟），不通自动落到 jsDelivr（`/api/update/status?refresh=1`）
- 只提醒、**不自动下载或替换任何文件**：有新版时左侧「设置」亮红点、启动弹 toast、设置页「更新」区块显示「版本状态」
- 打不开 GitHub 也能拿更新：设置页直接列出各直链与镜像，每条都带「打开 / 下载 / 复制」；「下载」走应用内通道——后端流式下载 + SHA-256 强制校验（不匹配立即删除半成品），文件落到下载目录，**替换 / 运行由用户手动完成**，不碰运行中的 exe，砖不了机
- mirrors 是否可信由发布者在 `update.json` 里把关；远端没给 sha256 时界面会明示「未提供校验值」；下载进度按秒轮询，刷新页面自动恢复
- 「发布页 ›」经系统默认浏览器直达 GitHub Releases；不想要某个版本的提醒可「忽略此版本」，下个版本会再提示
- 设置页可关「自动检查」；版本号只比数字段（`v1.4.2-beta` → `1.4.2`），`/latest` 天然排除 draft 与 prerelease
- 规则版本（歌单导入）沿用 `providers/manifest.json` 的 `update_url` notify-only 通道，与 `/api/update/check` 同一套

**导入歌单**
- **主通道：本地文件 / 粘贴文本** —— `.kgl`（酷狗客户端「播放列表 → 菜单 → 导出列表」）、`.txt`、`.csv`、`.m3u8`、纯文本「歌名 - 歌手」。零登录、不联网取数，格式多年稳定。文件按 UTF-8 读，遇到替换字符自动改用 GB18030 重读。
- **次通道：在线链接** —— 网易云 / QQ 音乐 / 酷狗歌单链接，支持分享文案里抠 URL 与短链跳转。网易云、QQ 音乐免登录可拿全量；酷狗旧式 `special/single/{id}` 全量，新版 `gcid_` / H5 分享链接免登录只给 10 首预览，界面会明示并引导改用本地导出文件。
- **可选增强**：酷狗凭据（token + userid）开关，默认关闭、只作用于当次请求，不写入 `data.json`。
- **三层筛选**：① 歌名 + 作者都严格对上 → 自动纳入；② 歌名对上、作者对不上 → 逐条声明出来，用户勾选才加入；③ 本地音源未找到 → 同样声明，可手动搜索指定。**不擅自合并、不静默丢弃**，预览全程 dry-run，点「导入所选」才落盘。分隔符方向由整批投票定一次，不逐条猜。
- 严格判定与换源、歌手归类同一套口径；歌单条目只接受 `kuwo` / `wyy`，别的平台原生 id 会在服务端被挡掉。
- 规则外置 `providers/*.json`（URL 匹配 / 端点 / 字段 / 探针）；`/api/providers/health` 按需自检三家接口，`/api/update/check` 做 notify-only 版本比对。改规则不必重发 exe。

## 播放内核

播放一律不直连 CDN，而是走本地 `/api/media`：

1. 前端点歌时**同步**拿到 `src`（只需曲目 id 与音质），`play()` 不会被 await 打断用户的点击手势；
2. 本地服务负责解析直链（链接失效时会自动重取），再把请求（含 `Range`）原样转发；
3. 远端返回 206 就回 206，**首播当场就能拖动进度条**，不用等整首下完；
4. 音频按 64KB 分块边收边发，起播速度不受文件大小影响；
5. 播放失败自动换下一档音质重试，全都失败才跳下一首，不会一路空跳；
6. 播到 98% 才第一次计算「听完」，关程序重开会恢复上次那首歌和进度。

## 播放引擎 2.0：无缝播放与均衡

1.x 只有一个 `<audio>`，曲末靠 `ended` 再 `play()`，中间有 150~250ms 的空档 ——
现场专辑的掌声会被切成两段。2.0 换成**双元素 + Web Audio 图**：

```
#audio   → gainA ┐
                 ├→ 10 段 EQ → master → 输出
#audio-b → gainB ┘
```

- **无缝**：曲末还剩 8 秒时就把下一首塞进备用元素开始缓冲；剩 160ms 时把它
  以 0 增益启动（此时已经解码出声，不会再有启动延迟），到点把两条增益反向拉过去。
  实测静音空洞 **0ms**（P4.0 spike 里「等 ended 再 play」的方案是 259ms）。
- **交叉淡入淡出**：可选 0.5 / 1 / 2 秒，同一套增益交叉拉长来做；不设就用 160ms 短交叉。
- **均衡器**：10 段 peaking（31Hz~16kHz），6 套预设加手动微调；增益变化走
  `setTargetAtTime` 平滑，切预设、开关都不爆音。
- 只有「顺序播放」启用无缝：单曲循环是原地重播、随机本来就跳着放，没必要预载。
- **可退**：设置里关掉引擎会把两个元素整个重建回原生路径 —— Web Audio 一旦接管
  就不可撤销，只有重建才真的回到 1.x 的确定性行为。
- Android 默认**不开**：目前只做了桌面验证，移动端 WebView 的
  MediaElementSource 要真机确认过才敢默认接管。

## 试听缓存：两层，按收听行为决定

缓存不是「听过就存」，而是**用收听次数投票**：

| 层级 | 进缓存的条件 | 清理规则 |
| --- | --- | --- |
| 今日缓存 | 当天**听完**同一首歌 2 次 | 跨天自动清空 |
| 长期缓存 | 最近 7 天内**听完**同一首 5 次以上（>5，即第 6 次） | 连续 3 天没再听就删除 |

- **未听完不计次**：只有播到结尾（或播过 98% 后切歌）才算一次；中途切歌、拖动跳过都不计数。
- 计数只保留最近 7 天，跨天自动滚出窗口。
- 升长期时是**把今日那份文件移过去**，不会重复占空间。
- 长期缓存被播放时会自动续命（刷新「最后收听时间」），所以常听的歌永远留着。
- 所有清理都在启动时和每次计数后执行，用户不用手动维护；设置里也能看当天已听多少首、两层各占多少。
- 缓存体积上限可调（默认 2GB），超出按最久未用淘汰。

## 多端同步：数据主权在你手上

收藏、歌单、播放进度可以同步到你自己的 WebDAV —— 坚果云、NAS、Nextcloud 都行。
没有中转服务器，没有账号体系，应用只在你填的地址上读写一个 `elysium-sync.json`。

- **只做加法**：本地已有的收藏和歌单，不会因为「远端没有」而被删掉。
- **拉取先看再动**：「从远端拉取」只算差异，弹出清单 —— 远端多出的收藏、新歌单、
  同 id 歌单的可补条目、同名但内容不同的分歧 —— 逐项勾选后才落盘。
  同名分歧给三选一：保留本机 / 用远端覆盖 / 两个都留。
- **同步什么、不同步什么**：同步收藏、歌单、播放进度；不同步设置（音量、主题、
  下载目录换台机器本就该不一样），也不同步收听统计与口味画像（那是这台机器的行为）。
- **本地曲目不上行**：`platform=local` 的 id 是本机绝对路径，换台机器毫无意义，
  打包时统一剔掉，顺带把磁盘结构挡在包外。
- **凭据不出门**：WebDAV 密码只存在本机 `data.json`，不回传给页面（页面只知道
  「设过没有」），脱敏导出里也不会出现。
- **自动上传默认关**：开了之后本地改动 5 分钟内最多推一次。启动时会探一次远端，
  那边有新内容只在设置里亮「远端有 N 项待合并」，**不会自动改你的数据**。
- 坚果云要用「应用密码」而不是登录密码；远端目录不存在会自动创建。

```
  /api/downloads/{cancel,retry,remove}
  /api/media             播放代理：解析直链 + 边下边播 + 写磁盘缓存（支持 Range）
  /api/media/warm        预加载下一首
  /api/play              记一次收听（听完计数 → 触发对应层缓存）
  /api/cache             缓存用量（今日 / 长期）/ 分层清理

  /api/update/check      规则版本比对，notify-only（远端 manifest 走 jsDelivr + 镜像兜底）
  /api/local/list        本地曲库扫描（下载目录，标签解析 + 签名缓存）
  /api/local/file        本地文件播放（磁盘直读，支持 Range，拒绝越界路径）

web/style.css            主题变量 + 组件样式
web/app.js               全部交互逻辑 + 播放引擎（双 audio / Web Audio / EQ）
web/lyrics.html          桌面歌词小窗页（独立轮询，不依赖主页面）
```

下载走 `DownloadManager`：固定 4 个线程的池子，按设置里的并发数限流；
每个任务先按降级顺序解析直链，再流式写盘，中途可取消，写完再补标签。

用户数据：`%APPDATA%\Elysium\data.json`（含同步凭据，不与任何人分享这个文件）
默认下载目录：`%USERPROFILE%\Music\Elysium`

两者都在**用户目录**下，与安装位置无关 —— 卸载程序不会带走数据，
换机器 / 换用户名时路径自动跟随当前用户（`data.json` 里若存着失效的
绝对路径，加载时会自动回落到本机默认目录，不会让下载静默失败）。

想分享自己的收藏 / 画像而不泄漏本机路径，用脱敏导出：
`GET /api/store/export` —— 会把 `download_dir` 换成占位符、去掉内部字段。

## 运行

**直接用成品**：到 [Releases](https://github.com/elysiayunchen/elysium-player/releases/latest) 下载
`Elysium.exe`（Windows 便携版，免安装）、`Elysium-setup.exe`（Windows 安装版，按用户安装，免管理员权限）
或 `Elysium.apk`（Android 版，Chaquopy 内嵌 Python 后端，构建配置在 [android/](android/)）。
需要 Windows 10/11 与 Microsoft Edge WebView2 Runtime。应用内置更新追踪，
有新版本会在「设置」亮红点并支持应用内下载。

**源码运行**：

```bash
pip install pywebview mutagen
python main.py             # 开桌面窗口
python main.py --browser   # 只起本地服务并用浏览器打开（开发调试）
python main.py --serve --port=18642
```

也可用环境变量固定端口：`set FLACMUSIC_PORT=18642`。

## 打包

Windows 下直接跑 `build.bat` 即可，它会自己找 pyinstaller
（依次尝试 `PYINSTALLER` 环境变量 → PATH → conda 常见位置），
不依赖任何特定机器的路径。

```bash
pyinstaller Elysium.spec --noconfirm   # 或手动执行
```

成品在 `dist/Elysium.exe`，单文件、免安装。

`Elysium.spec` 里有一条必须保留的处理：PyInstaller 会顺着 PATH 从
`PortableGit\mingw64\bin` 抓到 OpenSSL 3.5.x，而内嵌 Python 3.9 的 `_ssl.pyd`
链接的是 OpenSSL 3.0.x；版本对不上时加载 Windows 证书库会直接抛
`ssl.SSLError: [ASN1: NOT_ENOUGH_DATA]`，所有 HTTPS 请求全挂。
spec 里显式剔除了外来 OpenSSL 并改用 conda 自带的那份。

发布前可跑 `python check_release.py` 自检——扫个人数据（本机路径、密钥）与构建产物有没有混进工作区或 Git 历史。

## 命令行版

`cli/flacdl.py` 是同接口的轻量命令行工具，纯标准库、零依赖：

```bash
python cli/flacdl.py search 晴天
python cli/flacdl.py download 晴天 -n 1 --lyric
python cli/flacdl.py download "<单曲链接>"
```

## 借鉴来源

做之前翻了一圈同类开源项目，取了几处设计思路，代码全部自己实现：

- [lerdb/HotDownloader](https://github.com/lerdb/HotDownloader) — 下载队列的形态：并发 + 实时速度 +
  按音质自动降级 + 命名模板 + 同名策略 + 写标签。这几条基本成了本项目下载模块的骨架。
- [algerkong/AlgerMusicPlayer](https://github.com/algerkong/AlgerMusicPlayer) — 播放模式（顺序/单曲/随机）、
  播放队列、明暗主题切换的组织方式。
- [guohuiyuan/go-music-dl](https://github.com/guohuiyuan/go-music-dl) — 多音源「换源」的用户视角，
  促成了关联浏览的设计。
- [CharlesPikachu/musicdl](https://github.com/CharlesPikachu/musicdl) — 纯标准库、最小依赖的实现风格，
  命令行版 `cli/flacdl.py` 照这个思路写的。
