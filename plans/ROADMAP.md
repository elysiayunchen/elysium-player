# Elysium 产品路线图（v1.7 → v2.1）

> 2026-11-10 立项。8 个方向分三个里程碑推进，每个项目独立验收，互不阻塞（除 P4 依赖 P4.0 spike）。
> 原则不变：本地优先、零账号、notify-only、不静默合并 / 不静默丢弃、显式选择优于自动发现。

## P1 本地个性化推荐（v1.7）

**目标**：无账号、无上传的"每日 30 首"，把已埋的数据字段（`plays` / `feedback` / `taste_genres` / `personalized`）盘活。

**方案要点**
- 新增 `/api/discover/daily`：本地聚合生成候选池——收藏歌手热门曲 ∪ 高播放相似曲 ∪ 探索配额
- 口味画像：从 favorites(artist) + feedback(like) + plays 提取权重，首页展示"口味画像"面板
- 探索配额：≥30% 候选来自未收听过的艺人（防信息茧房），`taste_genres` 作多样性约束
- 反馈闭环：推荐结果行内 👍/👎 写入 `feedback`（结构已有），影响下一轮排序
- `personalized=false` 时入口整体隐藏
- 当日结果缓存（跨会话不重算），次日自动轮换

**验收（verify_daily.py）**
- 连续 3 天生成推荐，曲目重复率有上限
- 探索配额比例达标（≥30%）
- 👍/👎 后下一轮排序可见变化
- 断网状态下可用（纯本地，不新增任何上游请求）

**风险与对策**：推荐越推越窄 → 探索配额硬约束；上游无数据可用（收藏/历史全空）→ 显示引导态而非空列表。

## P2 歌词补全（v1.7）

**目标**：时间轴校准 + 双语歌词，高感知小成本。

**方案要点**
- 时间轴偏移：歌词面板与桌面小窗各加 ±0.5s 按钮；全局默认 `settings.lrc_offset_ms` + 当前曲目临时覆盖（不落盘）
- 双语 / 翻译行：优先用上游自带翻译（wyy 源多数带）；翻译行渲染为主行下方小字；无翻译优雅降级为现状
- 桌面小窗（lyrics.html）同步显示翻译行，跟随设置开关
- 不接第三方翻译服务（数据源不可控，守住边界）

**验收**
- 带翻译歌词的曲目双行渲染正确
- 偏移调整即时生效并持久化，重启后保持
- 小窗与主面板偏移一致

**风险**：上游翻译覆盖不全 → 界面不承诺"必带翻译"，有就显示。

## P3 听歌报告（v1.7）

**目标**：纯只读的本地收听统计，从"工具"到"陪伴感"。

**方案要点**
- `/api/stats/summary`：聚合 plays / recent / downloads / favorites——top 歌手 / 歌曲 / 风格、累计时长、24h 收听时段热力、天数与首听记录

**验收**

- 统计口径与收听计数一致（未听完不计）
- 无任何写操作（diff data.json 确认）

**延后项**：报告导出图片（分享卡）二期再议。

## P4.0 播放引擎 Spike（前置验证，先行独立）

**目标**：1~2 天验证 MediaElementSource 接管 `<audio>` 的可行性，决定 P4 走全量还是降级。

**验证清单**
1. 接管后 SMTC（mediaSession）元数据与媒体键是否完好
2. Range 进度拖动（206 边下边播）是否完好
3. `/api/media/warm` 预加载是否仍生效
4. 本地文件播放（/api/local/file）链路是否完好
5. Android WebView 对 MediaElementSource + 双 audio 的支持

**结论分支**
- 全通过 → P4 全量（gapless + crossfade + EQ）
- 部分通过 → 降级：只做 crossfade（不接管）或 EQ 仅桌面端
- 全不过 → P4 搁置，v2.0 只做 P5

### 桌面端结论（2026-11-10，`verify_engine.py` 15/15）

| 项 | 结果 | 实测 |
| --- | --- | --- |
| S1 接管后仍有声 | ✅ | 基线 peak 0 → 接管后 0.1187（不是静音假阳性） |
| S2 SMTC 链路 | ✅ | 元数据写入/读回一致，playbackState 正常，8 个 actionHandler 全可注册 |
| S3 Range 拖动 | ✅ | 端点回 206（`bytes 1000-1999/48988`）；seek 后位置到位且仍有声 |
| S4 双 audio 交替 | ✅ | A 播完 → B 出声，事件滞后 0ms |
| S5 提前切换 | ✅ | 剩 120ms 启下一首，最大静音空洞 0ms |

**尺子标定**：全场 0ms 太空不可轻信，故人为造 300ms 断音回测——测出 259ms，
说明 analyser 空洞检测能量出真实断音（也说明 10ms 采样精度下的下限约在 250ms 级；
真要抓几十毫秒的缝，P4 实施时得改成 `ScriptProcessor` / `AudioWorklet` 连续计数）。

**顺带修正立项时的两处臆断**
- 原清单第 3 项写的 `/api/media/warm` **这个端点并不存在**：`warm` 是 `MediaCache` 的方法，
  由 `cache_track()` 在计数触发时调用，前端没有预加载端点。所以「预加载是否仍生效」
  这一问在当前架构下不成立——gapless 的下一首预缓冲要靠新写的双 `<audio>` 自己 `preload`。
- S2 的 OS 观感（任务栏浮层 / 锁屏 / 媒体键）headless 看不见，只能证明 API 链路完好；
  真机确认列进 P4 验收。

**待补**：Android WebView 一项（需真机 / MuMu 实测），未跑不影响桌面端结论。

## P4 播放引擎 2.0：无缝播放 + EQ（v2.0）

**目标**：Live 专辑 / 古典乐章零间隙切换；EQ 与响度归一补齐发烧友定位。

**方案要点**
- gapless：双 `<audio>` 交替（A 播放中 B 预缓冲，曲末提前切换）；专辑顺序播放默认开，随机 / 单曲循环关
- crossfade：可选 0.5~2s 淡入淡出，设置项默认关
- EQ：BiquadFilter 链 10 段 + 预设（平直 / 低音增强 / 人声 / 古典 / 流行），设置持久化，开关切换无爆音
- 响度归一（二期）：按曲目增益补偿"有的歌大声有的小声"
- 98% 听完判定与 SMTC 切换时机适配双 audio 结构
- Android 若 spike 不通过：引擎 2.0 按端开关，Android 保持现有链路

**验收**
- Live 专辑连续曲目切换零间隙（时间戳级验证）
- 现有全部播放回归（verify_local / verify_ui / verify_drag）通过
- EQ 开关切换无爆音、无音量跳变

**风险**：动全产品最核心路径 → P4.0 前置 + 独立分支开发 + 全量回归后才合入。

### 实施记录（v1.8.0，2026-11-10，分支 feat/engine-2）

落地形态：`ENG` 模块持有两个 `<audio>` + 一张 Web Audio 图
（`src → gain → 10 段 EQ → master → destination`）。关键设计是让 `audio()`
**始终返回活动元素**，于是进度 / 音量 / 歌词 / SMTC / 续播那几百行一行没改。

- **无缝不是「等 ended 再 play」**：曲末剩 8s 预载下一首，剩 160ms 时以 0 增益
  启动备用元素（此时已解码出声，没有启动延迟），到点把两条 gain 反向 ramp。
  这把空档从 P4.0 spike 实测的 259ms 压到 **0ms**。
- **踩到的两个坑**（都已修，写进代码注释）：
  1. 交叉后新曲剩余时间若仍小于预载阈值，会立刻二次预载，而备用元素正是**还在
     淡出的旧元素** —— `load()` 抢走 src，把淡出腰斩成一段真静音。加了元素级
     `__coolUntil` 冷却。
  2. 上一轮交叉被打断时 gain 会停在半路，手动起播前需 `engGainReset()` 拉回 1。
- **EQ**：10 段 peaking + 6 套预设，`eq_gains` 是唯一真相（预设只负责往里填数），
  增益走 `setTargetAtTime` 平滑；关闭时把各段置 0 dB 而不是拆图，切换不爆音。
- **可退**：`engRebuild()` 关掉引擎时把元素整只重建 —— Web Audio 接管不可撤销，
  只有重建才真的回到 1.x 路径；切换时按原位置续播。
- **验收**：`verify_gapless.py` 16/16（空洞 0ms、交叉重叠 1420ms、EQ 500Hz 段
  -12dB 使 440Hz 衰减 44%、降级路径仍能播）；回归 verify_local 17/17、
  verify_engine 15/15、verify_ui 20/20、verify_drag 6/6。
- **待补**：Android 真机确认后把 `engine_v2` 的默认值放开（现在按平台判断，
  桌面开、Android 关）。

## P5 多端同步 WebDAV（v2.0）

**目标**：Windows / Android 双端收藏、歌单、进度同步，数据主权在用户（坚果云 / NAS）。

**方案要点**
- 后端新增 sync 模块：纯标准库 WebDAV 客户端（http.client，随项目风格）
- 上行 `/api/sync/push`：脱敏打包（复用 export 脱敏逻辑）+ 时间戳 + 设备名 → PUT
- 下行 `/api/sync/pull`：GET + **dry-run diff 预览**（新增 / 变更 / 冲突三列展示，沿用导入哲学）→ 用户勾选后 commit
- 合并语义分层：收藏 / 歌单条目按 key 并集合并（天然无冲突）；同名歌单内容分歧时并列让用户选；设置类不同步
- 自动模式（默认关）：启动拉一次 + 变更防抖推送（间隔 ≥5min）
- 凭据存 data.json（与现有数据同级安全等级），设置页明示；凭据绝不进 export

**验收**
- 双实例（双端口隔离）互推互拉回归
- dry-run 阶段零写入（diff data.json）
- 断网重试与失败明示，不静默丢数据
- export 输出不含 WebDAV 凭据

### 实施记录（v2.0.0，2026-11-10）

新增 `sync_engine.py`（与 importer.py 平级，bind 注入 store，不 import main），
纯标准库 WebDAV 客户端（http.client + Basic Auth，`MKCOL` 逐级建目录）。

- **同步边界**（写死在 `pack()` 的字段白名单里）：收藏 / 歌单 / 播放进度。
  本地曲目（`platform=local`，其 id 就是本机绝对路径）打包时统一剔除；设置、统计、
  口味画像一概不同步。
- **合并语义**：收藏按 `(kind,id,platform)` 并集；歌单按 id 并集，同 id 补条目按
  `(platform,id)` 去重；**同名不同 id 判为分歧**（`local` / `remote` / `both` 三选一）；
  进度按 `at` 大者胜，且本地听得更靠后时不往回退。
- **不静默合并**：`/api/sync/pull` 只算 diff 不落盘，`/api/sync/commit` 才写；
  本地数据只增不删。
- **凭据处理**：`/api/store` GET 把 `webdav.pass` 剥掉换 `has_pass`，前端拿不到明文；
  `configure` 收到空密码视为「沿用」；`/api/store/export` 里 `pop("webdav")`。
- **自动模式**（默认关）：只自动上传（5 分钟内最多一次，`touch()` 打标记）；
  启动探一次远端只更新 `pending` 提示，不改本地 —— 自动也不破「不静默合并」。
- **验收**：`verify_sync.py` 26/26（内存 WebDAV 替身 + 双实例互推互拉：包体不含
  local/凭据/本机路径、dry-run 前后业务字段指纹一致、三类合并、进度取舍、export 脱敏、
  断网明示）；回归 verify_gapless 16/16 / verify_local 17/17 / verify_ui 20/20。
- **延后**：`recent`（最近播放）不同步 —— 它偏行为日志，两端混在一起会脏；真要同步
  得先定一份去重与时效规则，属于二期。

## P6 托盘 + 迷你模式（v2.1）

**目标**：桌面播放器标配体验——关窗不停歌 + 迷你悬浮条。

**方案要点**
- 托盘：倾向 pystray（稳定，体积 +~2MB 可接受；备选纯 win32 Shell_NotifyIcon 免依赖但实现重）
- "关闭按钮行为"设置项：退出 / 最小化到托盘，**默认保持退出**（不惊喜原则）
- 托盘菜单：播放暂停 / 上一首 / 下一首 / 显示主窗 / 退出
- 迷你模式：主窗口切换为 frameless 悬浮条（复用桌面歌词小窗的工程模式）——封面 + 控制 + 当前行歌词
- Android 不适用（原生通知栏已覆盖）

**验收**
- 退出 / 崩溃后托盘无僵尸图标
- 双击托盘还原窗口，托盘控制即时生效
- 迷你条拖动、贴边、还原全流程

**待决策**：默认关闭行为（退出 vs 最小化）上线前定。

### 实施记录（v2.1.0，2026-11-10）

- **托盘**：pystray + Pillow（+约 3MB，接受）。菜单：显示主窗口 / 播放暂停 /
  上一首 / 下一首 / 退出。图标复用 app.png，取不到就退回纯色块，绝不因此起不来。
- **关闭行为默认「退出」**（按「不惊喜」原则定的）：设置里可改「收进托盘继续放」。
- 三条安全线（都有 `verify_win.py` 守着）：托盘图标没起来时一律真退出，绝不把窗口
  藏没了；从托盘退出时先摘掉窗口引用再 destroy，否则 closing 拦截会把退出卡住；
  pystray 装不上时 `start_tray` 返回 False，主功能一点不受影响。
- **迷你条**：主窗口 `resize(430, 138)` + `on_top`，贴屏幕右下角，记录原尺寸可还原。
  前端靠 `html[data-mini="on"]` 切布局 —— 隐藏侧栏/顶栏/右半段，`.pl-m` 用
  `display:contents` 拆开让控制组上右、进度条落底（420px 宽塞不下三段式）。
  拖拽用真实元素挂 `.pywebview-drag-region`（伪元素不被 pywebview 识别）。
- **未验证**：托盘的 OS 观感（任务栏图标、右键菜单、双击还原）与迷你条的
  真机拖动必须在实机上看 —— 沙箱里的 GUI 进程活不过命令结束，只能测逻辑。
  布局本身用 CDP 强制视口 430×138 验过（Chrome 有最小窗口尺寸，直接 resize 会被夹住）。

## P7 本地曲库管理（v2.1）

**目标**：范围从"只扫下载目录"正式扩展为"用户显式添加的目录"——守住"显式选择"哲学，不做全盘自动扫描。

**方案要点**
- 设置页"曲库目录"列表：添加 / 移除，默认仍仅下载目录（老用户零变化）
- 增量扫描：mtime / size 签名缓存（本地音乐已有签名缓存机制，沿用），只处理变更
- 大曲库：后台线程扫描 + 进度反馈 + 首批秒级返回 + 滚动分批渲染（歌手页已有先例）
- 乱码兜底：标签读不出整段用文件名（沿用现有哲学），绝不因单文件失败中断
- **明确不做（写死边界）**：标签编辑、全盘扫描、跨目录去重合并

**验收**
- 10k+ 文件目录扫描首批秒级返回，全量扫描有进度
- 二次扫描仅处理变更项（耗时数量级下降）
- 移除目录只解除关联，不删任何文件

### 实施记录（v2.1.0，2026-11-10）

- **曲目 id 的兼容处理**是这次最关键的一处：0 号根（下载目录）的 id 保持
  「纯相对路径」不变 —— 老收藏、老歌单里存的就是这个格式，改个前缀等于把用户
  的库弄丢。只有额外目录才带 `@n/` 前缀，`_local_split()` 统一解析。
- **增量**：签名 = (根目录列表, 文件数, 最新 mtime)；单文件标签按 mtime 缓存，
  重扫只读变过的。签名没变且 120 秒内直接吃缓存。
- **大库异步**：超过 800 个文件先做「文件名占位」列表返回（不读标签），
  再起后台线程逐条补标签、推进进度；前端只重写头部那行字，不整页重绘
  （否则滚动位置一直被弹回顶部）。
- **越界**：`_local_split` 之后再走 realpath + 前缀校验，`@1/../x.mp3` 一律拒绝。
- **不做**（写死边界）：标签编辑、全盘扫描、跨目录去重合并。
- **验收**：`verify_lib.py` 19/19（多目录 / id 兼容 / 越界 / 去重 / 增量 / 移除 /
  1201 文件首批 202ms + 后台 3.0s 补完 / 坏文件兜底）。
