## 一、总评

底子在独立开发的音乐应用里属上游水平。「深色取 Spotify 的密度、浅色取 Apple Music 的通透」
（style.css:3 自述）在成品里是兑现了的：双主题 token 体系完整、粉色 accent 有品牌辨识度、
mono 等宽数字、双主题空态插画、骨架屏、音质徽标「只认实测」三态是全产品最有诚实感的一笔。

短板集中在两处：

1. **错误态完成度远低于空态**——歌词失败直接渲染成 42px 巨字，无重试、无建议动作。
2. **可达性系统性缺位**——焦点不可见、图标按钮无 aria-label、动效无 reduced-motion、
   toast 无 aria-live。

## 三、审美层：问题

### P1 歌词错误态是巨字败笔
- `app.js:3779` 把 `<span class="muted">取歌词失败：请求已过期</span>` 直接塞进 `.np-lyric`，
  而该容器字号 `clamp(26px,3.1vw,42px)/700`（style.css:1802）——错误继承歌词巨字样式，
  左上角孤零零一行灰字，无重试按钮、无图标、无建议动作，且暴露内部措辞「请求已过期」。
- `app.js:4876` 桌面歌词层同款问题。

### P2 浅色主题次要文字对比度不达标（实测）
| 组合 | 对比度 | AA 4.5:1 |
|---|---|---|
| 深色 --muted #7b7b8a on 卡片 #12121a | 4.47:1 | 踩线 |
| 浅色 --muted #86868f on 白卡 | 3.61:1 | ❌ |
| 浅色 muted on 背景 #fbfbfd | 3.49:1 | ❌ |
| 浅色 accent #f5325b 作正文色 | 3.70:1 | ❌ |

浅色 --muted（style.css:56）大量用于副标题/kicker/说明文字，建议提亮约 10%（如 #6e6e78）；
深色 4.47 也踩线，顺手一起调。

### P2 双主题 token 不对称 → 切换时布局跳动
- --h1 深色 34px / 浅色 42px、--radius 10px/11px（style.css:34,67）。切主题时标题与圆角全变，
  页面明显重排；叠加整页重渲染，推荐封面短暂闪白（实测复现）。
- 建议保留策略但收窄 h1 差距，或切主题对卡片做淡入。

### P2 视觉噪音与密度
- 进收藏库/搜索页时整列「检测中」徽标同时脉冲（可持续数秒），25 行闪烁面偏大；
  批探测已是 12 条一批（app.js:270 注释），但渲染仍整列一次性。
- kicker 9.5px + .2em 字距（style.css:92-96）过小，10.5-11px 更稳。
- NP 队列视图 1440 宽下 760px 居中窄列（style.css:1818），左右大片真空，
  与歌词视图满宽排版气质割裂。

### P2 K 歌底部 dock 图标暗底不可见
暖棕渐变上伴奏/麦克风/人声滑杆图标几乎不可见（实测截图），第三个滑杆看起来「没有主人」；
需统一提亮或加底衬。

### P3 首页移动端快捷卡奇数失衡
2 列网格下「收藏本」孤行（390px 实测）。改 3 张横滑或第三张占满整行。

### ~~P3 音质菜单半透明底透字~~（更正：误判）
复查 qmenu 样式为实色 var(--bg-soft)、无 alpha 无 backdrop-filter；初查截图实为
「菜单遮住 QUEUE·1 前两个字母」。不构成问题，未改动。

### P3 其他
- NP 队列当前行指示是静态 ▶（app.js:3454），列表行已有 eq 均衡器动画（app.js:1998），
  两处不一致，队列行也应使用 eqHtml()。
- 首页信息密度偏高（hero+3 快捷卡+CONTINUE+推荐+最近播放），章节间缺呼吸感。

## 四、交互设计排查

### 做得好的
- 键盘全覆盖：Space 播放/暂停、←→ 快进退、↑↓ 音量、L 歌词、Q 队列、M 静音、/ 与 Ctrl+F
  聚焦搜索、Escape 逐层关闭（app.js:5413-5437）。
- 行级交互：整行点击即播、悬停序号变播放键 + 收藏/下载浮现、右键自绘 contextmenu（app.js:5459）。
- 手机抽屉点导航自动收起（app.js:5206-5209）+ 窗口拉宽自动归位。
- 拖拽排序队列、请求序号防回填（artistSeq）、搜索防抖。

### 问题

**P1 键盘焦点整体不可见 + role=button 卡片不可激活**
- 全 CSS 无 :focus-visible，多处 outline:0。
- 推荐卡 role="button" tabindex="0"（app.js:2243）但无 Enter/Space 激活处理；且 Space 被
  全局监听拿去播放/暂停（app.js:5416）——聚焦卡片按空格触发的是全局播放，认知错位。
- 修法：全局 `:focus-visible{outline:2px solid var(--accent);outline-offset:2px}`；
  给 [role=button] 补 Enter/Space 激活（激活时 stopPropagation）。

**P1 错误反馈只有 toast 一种形态**
- 搜索/加载/链接解析失败全是 `toast('搜索失败：'+e.message,'err')`（app.js:4981,4998,5014）。
  toast 自动消失 + 无 aria-live；失败应至少给 in-place 状态与重试入口。

**P2 搜索不进返回栈**
- go()/openAlbum/歌手/歌单都 push（app.js:3391,5027,5057,5077），唯独 doSearch 直接赋
  state.route（app.js:4967）→ 从首页搜索后顶栏返回按钮禁用，但用户明明来自首页。
- 修法：doSearch 补 push（搜索状态本就保留，无副作用）。

**P2 移动端 mini player 可达热区太小**
- NP 展开只绑在 48px 封面（app.js:5180 #plArt），标题/歌手区点了没反应（390px 实测确认）。
  惯例是除控制按钮外整个 mini bar 可点开全屏。

**P2 移动端顶栏拥挤**
- 390px 下 汉堡+返回+搜索框+主题+队列 5 组元素，搜索框压到 ~180px（实测）。
  主题切换移动端属低频，建议收进抽屉/设置。

**P3 触屏上悬停操作无可见替代路径**
- 推荐卡四操作 hover 浮现（style.css:1295，有 :focus-within 兜底）；触屏无 hover 无焦点，
  只剩右键/长按 contextmenu 兜底，路径不可发现。

## 五、可访问性（需系统性补课）

1. 图标按钮无障碍名：index.html `title=` 43 处 vs `aria-label` 仅 3 处；title 不稳定且触屏无 tooltip。
2. toast 无 aria-live：`<div class="toasts" id="toasts">`（index.html:382）加 role="status" 即可。
3. 无 prefers-reduced-motion：55 处 transition + 4 组无限动画（eqbar/spin/sh/skelpulse）。
4. 进度条无 slider 语义：.seek 是纯 div（index.html:164,223），无 role="slider"/aria-valuenow。
5. 列表行无语义：.tr 行是 div 堆叠，缺 role="table"/"row" 或列表语义。
